# Что было вырезано и чем заменено

## Удалено

- общий перегруженный обработчик меню;
- ручное обновление списка RedGIFs-ниш;
- сканирование каталога `/niches`;
- старые `reference_models`, `reference_niches`, остальные `reference_*` и `ref3_*` таблицы целиком;
- временная загрузка склада в личку владельца;
- доставка референсов через `file_id`;
- автоматическое наследование ошибочно назначенного старого склада;
- смешивание групп моделей с каналами креативов.

## Новые модули

- `bot/main-menu.ts` — только главное меню;
- `bot/creative-menu.ts` — только креативы;
- `bot/reference-menu.ts` — только референсы;
- `bot/access-menu.ts` — только доступ;
- `creative-queue.ts` — durable-очередь Instagram;
- `reference-queue.ts` — каталог, scan leases, warehouse uploads, group deliveries;
- `reference-catalog.ts` — статический утверждённый каталог;
- `store.ts` — KV-настройки без смешивания разделов.

## Защита от дублей

После успешной отправки в Telegram desktop сначала пишет локальную durable-квитанцию в SQLite и только потом подтверждает Worker. Если соединение пропало после отправки, следующий запуск подтверждает уже выполненную операцию и не загружает/копирует ролик повторно.

Квитанции существуют отдельно для:

- публикации на склад;
- копирования в группу модели.

## Состояние после установки

- креативные места публикации переносятся из предыдущих ключей;
- старые reference-таблицы физически удаляются; reference-группы и reference-очереди начинаются чистыми;
- склад нужно назначить заново один раз;
- сбор референсов включается автоматически после назначения склада;
- 473 ниши распределены по часу и далее каждая сканируется раз в час;
- HOT-5 — жёсткая глубина одного прохода, не лимит накопления или доставки. Другие сортировки не используются.
- глобально отключённая ниша остаётся в утверждённом каталоге, но не получает scan lease и не маршрутизирует новые доставки; выбор этой ниши у групп сохраняется для возможного повторного включения.


## Telegram update inbox

Webhook больше не считается успешно обработанным заранее. Каждый `update_id` сначала получает lease в Durable Object, после успешной обработки помечается `done`, а при исключении lease освобождается и Telegram может повторить update. Это защищает кнопки и команды от параллельных дублей без старого KV `get → put` race.

## Разделение ролей чатов

Один Telegram-чат не может одновременно быть:

- местом публикации креативов;
- складом референсов;
- группой модели.

Проверка выполняется при каждой привязке, чтобы неправильное назначение физически не могло смешать два контура.
